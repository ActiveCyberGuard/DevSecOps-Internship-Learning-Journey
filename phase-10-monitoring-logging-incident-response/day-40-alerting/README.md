# Day 40 — Monitoring Alerting

 

## Overview
Learned monitoring alerting. Practiced using Prometheus alert rules to detect when a monitoring target becomes unavailable.

## Objectives
- Understand what an Alert and an Alert Rule are
- Understand Prometheus expressions
- Create an alert condition
- Configure alert duration and severity
- Understand firing and resolved alert states

## What is an Alert?
A warning or notification generated by the monitoring system when a predefined condition is satisfied.
```
Application Down
       |
Condition TRUE
       |
Alert
```

## Alert Rule
File: `rules/alerts.yml`
```yaml
groups:
  - name: devsecops-alerts
    rules:
      - alert: PrometheusTargetDown
        expr: up == 0
        for: 1m
        labels:
          severity: critical
        annotations:
          summary: "Monitoring target is down"
          description: "A monitored target is unavailable."
```

## Alert Rule Explanation

| Field | Value | Meaning |
|-------|-------|---------|
| Alert name | `PrometheusTargetDown` | Name of the alert |
| Expression | `up == 0` | True when a target is unavailable |
| Duration | `for: 1m` | Fires only if the condition stays true for 1 minute |
| Severity | `severity: critical` | Priority level of the alert |

## Commands Used

| Command | What it does | Why |
|---------|---------------|-----|
| `docker ps` | Lists running containers | Confirm Prometheus is running |
| `docker logs prometheus` | Shows container logs | Check for errors |
| `docker start prometheus` | Restarts the Prometheus container | Restore the target after testing |

## Alert Testing
Stopping a monitored target triggers the alert condition. After testing, the service is started again to resolve the alert.
